# DH-00B — Experience principles

1. **Exploration over presentation.** Make curiosity worthwhile.
2. **Immediate usefulness.** Direct URLs, search and an accessible project index must always work.
3. **Character over gimmicks.** Humour should emerge from environment and interactions, not forced jokes.
4. **An evolving place.** New projects should slot in without rebuilding the experience.
5. **Fast to first interaction.** Progressive loading of heavy media and scenes.
6. **Mobile first-class.** Adapt the metaphor if needed, rather than squeezing a desktop world into a phone.
7. **Access for everyone.** Keyboard focus, readable labels, contrast, reduced motion and non-spatial navigation.
8. **No audio ambush.** Respect autoplay restrictions and user control.
9. **Celebrate the process.** Failed, abandoned and in-progress work can be interesting.
10. **Independent projects.** Link to existing apps and builds; do not intertwine their code or release systems.
11. **No surprise disclosures.** Nothing becomes public simply because a connector can see it.
12. **Performance is part of the art.** A novel interface still has to work well on ordinary devices.
13. **Strangeness with visual discipline.** The design should be distinctive without becoming a collage of arbitrary objects or styles.
14. **An original mindscape.** Explore the Dave-head-to-Dave-Machine transition without using a realistic likeness, and treat the intro as optional.

## Avoid

- Stock homepage → project grid → skills → contact section.
- Unskippable introductions or compulsory tutorials.
- Secret-only navigation, with no accessible escape.
- Large 3D worlds populated mainly with ordinary web cards.
- Premature framework/CMS/database complexity.
- Terry Gilliam / Monty Python cut-out aesthetics, paper-puppet motion, grotesque collage, Victorian scrapbook styling, default steampunk gears and random mechanical clutter. This is a hard exclusion across all three concepts.
