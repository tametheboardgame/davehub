# DaveHub public-content and privacy policy

**The GitHub repository is public.** Treat every commit as immediately readable on the internet, even if the website itself has not been deployed.

## Suitable in principle

- Original work the author owns and has permission to publish.
- Approved screenshots, gameplay clips, devlogs and public release notes.
- Synthetic/public-safe technical demonstrations.
- Links to repositories and builds already deliberately public.

## Permission gates

- **Employment, supplier or customer systems:** never disclose internal configuration, diagrams, security findings, data, identifiers or screenshots without appropriate authorisation.
- **Real people in games or recordings:** check permission to publish their likeness, voices and identifying information.
- **Third-party music, art, text, software and trademarks:** check copyright, licences and approvals.
- **Private projects:** do not disclose filenames, metadata, excerpts or source merely because a connector can read them.

## Publishing workflow

1. Classify each item: `Public approved`, `Needs review`, or `Private`.
2. Only explicitly approved items may appear in the public catalogue or promotional materials.
3. Review title, descriptions, preview media, outgoing links, people and provenance.
4. Automated integrations may draft content, but **must not publish automatically**.
5. Keep approval history and an ability to correct or withdraw material.

Never commit secrets or credentials. Use secret storage for deployment settings. External integrations are read-only by default. Do not automatically publish private project changes.
